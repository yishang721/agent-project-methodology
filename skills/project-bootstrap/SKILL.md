# Project Bootstrap（项目启动三件套）

单一权威方法论：项目如何启动、如何收尾、记忆与活文档如何提纯、坑往哪沉淀。
口令协议细节以 handoff 技能模式 B 为准，本技能不重复抄。

## 1. 判级（启动前先判，明说结论）

| 级别 | 判据 | 启动物 |
|---|---|---|
| heavyweight | 跨多周 / 跨多对话 / 可能移交其他 agent 或工具 / 多线并行 | 三件套全套：项目 memory + 活文档（handoff 模式 B） |
| 轻量 | 一次或几次对话能收尾、无移交预期 | 仅项目 memory |

判级权在 AI，启动时必须明说「本项目按 heavyweight / 轻量跑」及理由。拿不准取 heavyweight。

**判级后方案对齐**：heavyweight 判定后若关键规格/目标仍未对齐（未决项 ≥3 或用户需求描述含糊）→ 先跑 `grill-me` 拷问对齐（逐分支收敛决策），再落三件套；grill-me 未安装则 AI 以逐题澄清方式替代（每题先给推荐答案）；轻量项目跳过此步。

## 2. heavyweight 启动流程

1. **建项目 memory**（项目 `.workbuddy/memory/MEMORY.md` 或独立主题文件）：只放指针 + 硬规则 + 「犯过的错」段，不放过程叙事。
2. **建活文档**：按 handoff 技能模式 B 生成 `【事项名】交接文档.md`，放**项目文件夹内**（禁放临时目录），十板块结构，未决项标★。
3. **写开工硬规则**（项目 memory 第一行，动作化）：
   - 新对话开工前：读活文档（开场口令「阅读交接文档，准备开始」）→ 检索本仓库 `pitfalls/` 踩坑索引（Grep 症状行，命中再读对应域文件卡全文）→ 汇报理解（3-5 条）→ 用户点头才动手。
   - 收尾必更活文档（收尾口令「结束对话，总结项目」）。

## 3. 收尾触发（三层，全部 prompt 层，不建 automation）

1. **口令**：用户说「结束对话，总结项目」或近似 → 走 handoff 收尾协议。
2. **AI 主动询问**：检测到里程碑完成 / 「先这样、今天到这」类语义信号 → 主动问「要收尾更新活文档吗」。每会话最多问一次。
3. **硬规则自检**：项目 memory 已写死收尾义务，每次会话注入必然可见。

## 4. 收尾时的坑分流（三级，先落点再删）

| 坑的性质 | 去向 |
|---|---|
| 项目内一次性坑（版本号、路径、本项目参数） | 项目 memory「犯过的错」段 |
| 跨项目可复用坑（工具行为、通用解法） | 本仓库 `pitfalls/`：症状式标题 + 标签 + 可复制对策 + 来源 + ⏳✅❌ 状态；每域一个 md 文件，改完重跑 `python tools/build_index.py pitfalls/` 再生总索引 |
| 状态类信息（进度、决策、待办） | 活文档对应板块 |

活文档**只留指针不留坑的正文**（一行指针 → 指向项目记忆或对策卡）。

## 5. 提纯（四要素，缺一不算提纯）

- **阈值**：活文档正文（一~八板块）>200 行，或「九、对话信息记录」>10 条 → 触发；项目 memory 超出所在 harness 的注入上限（WorkBuddy 当前版本：项目级 8000 字符 / 用户级 4000 字符，按字符数计）→ 必须提纯，建议留 200 余量。
- **时机**：收尾协议执行时顺手检查，不设独立仪式。
- **动作**：五步制——①备份 `cp` ②`wc -c` 验证备份字节数=原文件 ③改写 ④回读复验（字符数+改动点） ⑤数字汇报。禁止声称完成代替验证。
- **去向**：先落点再删（按 §4 分流表）；「十、更新记录」永不折叠（账本完整性）；细节正文去母本文件，活文档留一行指针。

## 6. 项目 memory 形态标准

- 第一行：开工/收尾硬规则（见 §2.3）。
- 正文：指针（活文档路径、权威资料路径）+ 硬规则 + 「犯过的错」段。
- 禁止：时间戳叙事、过程叙述、与活文档重复的状态信息。
- 自检：改完必测字符数，例如 `python -c "print(len(open(path,encoding='utf-8').read().strip()))"`。

## 7. 与其他机制的关系

- 口令协议 / 十板块 / 开场收尾细节 → `handoff` 技能模式 B（本仓库 `skills/handoff/`，需一并安装；本技能只管何时建、怎么提纯、坑去哪）。
- 坑的沉淀与检索 → 本仓库 `pitfalls/`（每域一文件）+ `tools/build_index.py`（自动生成总索引，勿手改）。
- 方案拷问（判级后对齐）→ [grill-me](https://github.com/mattpocock/skills)（可选外链，未装自动降级）。
- 能力冷库治理 / 路由路由表（进阶）→ [Table-GitHub-Capability-Router](https://github.com/duoduoler-ops/Table-GitHub-Capability-Router)（本仓库 pitfall 三态生命周期即对其状态机的简化致敬）。
