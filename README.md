# agent-project-methodology

**中文：项目启动三件套 × 交接文档** —— 让 AI 助手把项目「记在文件里」而不是「记在聊天里」。

---

## 你的 AI 项目正在经历三宗罪

1. **换个新对话，AI 失忆** —— 需求、约定、进度从头再讲一遍。
2. **换一个 AI 工具，规矩全部作废** —— 之前调教好的工作方式清零重来。
3. **上个月踩过的坑，这个月原样再踩** —— 教训散落在聊天记录里，从未被系统沉淀。

**根因有两个，第二个更隐蔽**：

- **根因①：项目状态活在聊天记录里，而聊天记录不属于任何项目。** 会话一关，一切蒸发。
- **根因②：就算写进了记忆文件，注入管道还有隐形上限。** 我们的项目记忆曾膨胀到 45KB（约 1.5 万字符），而 WorkBuddy 的注入上限是硬编码的 8000 字符（按字符数计，非字节；用户级仅 4000）——**近半内容被静默截断**，AI 只引用前一半，用户看到的只是"AI 忘事"。反查源码才实锤。任何 harness 的记忆注入都有隐形上限，**记忆文件不是越大越好**。

这就是本方法论两个核心设计的由来：**状态进文件**（治根因①）、**记忆只留指针**（治根因②）。都是被真实事故逼出来的，不是审美偏好。

## 装了它能做到什么

两份技能文件（AI 可读的 Markdown 指令），装进你的 AI 助手后：

### 1. 项目档案化

新项目开工时，AI 自动判级（heavyweight / 轻量），heavyweight 项目当场建立三件套：

| 件 | 内容 | 治什么 |
|---|---|---|
| 项目记忆 | 只放指针 + 硬规则 + 「犯过的错」，**≤7800 字符** | 注入截断 |
| 活文档 | 十板块交接文档，放项目文件夹内，随收尾自动更新 | 会话失忆 |
| 开工硬规则 | 写进项目记忆第一行，每次会话注入必然可见 | 规矩作废 |

### 2. 两句话接管全局

- 开工：对 AI 说「**阅读交接文档，准备开始**」→ 它汇报理解（3-5 条）、列待办、**等你确认才动手**。
- 收尾：说「**结束对话，总结项目**」→ 它更新文档、沉淀新坑、追加「第 N 次对话」记录（不删历史）。
- 无需复述任何背景。换对话、换账号、换工具，打开同一份文档就能无缝接续。

### 3. 踩坑复利

收尾时 AI 按三级分流沉淀踩坑：

- 项目内一次性的坑 → 项目记忆「犯过的错」段
- 跨项目可复用的坑 → 对策卡（症状 → 对策 → 来源 → ⏳✅❌ 三态状态）
- 活文档只留一行指针，永不堆积

附带的索引脚本（56 行纯标准库 Python）自动生成踩坑总索引——坑越攒越多，重复踩的越来越少。

### 4. 收尾自动提纯（防膨胀）

文档只会长，不会自己瘦。收尾时 AI 顺手检查：活文档正文 >200 行或对话记录 >10 条即触发提纯；改任何记忆文件走五步制（备份 → 验证字节数 → 改写 → 回读复验 → 数字汇报）。**「声称完成」不算完成，数字说话**——这条来自一次真实事故：AI 声称"已全量备份"，实际归档只落了 6.4KB，45KB 原文一度丢失。

## 怎么装（约 5 分钟）

把 `skills/` 下两个文件夹拷进你 AI 工具的技能目录：

| 技能 | 中文名 | 必装？ |
|---|---|---|
| `skills/project-bootstrap/` | 项目启动三件套 | ✅ 必装 |
| `skills/handoff/` | 交接文档 | ✅ 必装（硬依赖：口令协议与文档模板在这里） |
| grill-me（外部，可选） | 方案拷问 | 🔗 见 CREDITS，未安装时 AI 自动降级为逐题澄清 |

- **WorkBuddy / zcode**：拷到 `~/.workbuddy/skills/`（或 `~/.zcode/skills/`）。
- **Claude Code / Codex 等支持 SKILL.md 的环境**：拷到对应技能目录即可（frontmatter 中的 `display_name` 等字段会被无害忽略）。
- 装好后，对一个新项目说「**开始一个新项目**」——AI 会判级并说明理由，你确认后三件套落盘。

**磨合期提示**：装完不等于立刻听话。规则是生长式的——前 2~3 个项目里 AI 每次执行判级、收尾、提纯时你把一把关，纠偏两三次后即稳定。

## 注意事项

- **破坏性操作默认举手**：删除、覆盖、对外发送，AI 必须先问你再做（技能里已写死）。
- **口令可以自然语言变体**：不必逐字背诵，意思到位即触发。
- **纯本地运行**：零网络请求、零账号、零 API key。唯一可选外部依赖是 grill-me（MIT，外链安装）。
- **未决项标 ★**：AI 不替你做决定——活文档里所有未拍板事项带 ★ 留给你。
- **license 与署名**：MIT。方法论受益于多位分享者，详见 [CREDITS.md](CREDITS.md)——包括「交接文档驱动」工作法的原创者与能力冷库治理体系的作者。

## 设计原则（为什么长这样）

- **按文件接管，不按聊天记录接管**——项目是文件的事，账号和对话只是入口。
- **记忆是检索索引，不是仓库**——大而全必然撞注入上限；一行指针 + 权威文件才是可扩展结构。
- **声称 ≠ 事实**——所有写操作必须验证后汇报，数字说话。
- **规则生长式**——先精炼跑通，反复出现的教训才升格为规则；不一次写一百条。
