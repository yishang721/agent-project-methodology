〇、协作约定（此段原样保留在文档里，一字不改）
本文档用于「交接文档驱动」的跨对话协作，所有状态以本文档为准。
- 用户说"阅读交接文档，准备开始"或意思相近的说法 → 按开场协议执行
- 用户说"对话结束，总结项目"或意思相近的说法 → 按收尾协议执行
- 多份交接文档按名称或最近更新定位；无法确定时列出候选让用户选。
- 开场协议：①用3-5条汇报对目标/进度/关键结论的理解 ②列出下一步待办并给建议 ③有明确风险才单列，没有则整段省略 ④以"你想先开始做什么？"结尾
- 收尾协议：①把一~八板块更新到最新状态 ②把本次对话中用户新告知的信息、新提出的要求或方法，追加到「九、对话信息记录」 ③在「十、更新记录」末尾追加：第N次对话（N=现有记录条数+1）、当前日期时间、本次改动 ④不删除、不覆盖历史记录，未决项已解决移入已确认、未解决保留标★ ⑤输出确认"已更新交接文档，新增第N次记录"

对话类型：项目开发

## 一、背景与目标

个人博客站点（静态 HTML + 少量 JS）改版：视觉刷新为暗色主题 + 移动端适配。范围只做前端呈现与构建脚本，不动文章内容。

## 二、关键规格与结论

- 暗色主题底色 `#0f1420`，正文 `#e8e8ea`，强调色青色系；标题用系统字体栈，正文 16px/1.8。
- 移动端断点 768px；导航折叠为汉堡菜单；图片懒加载。
- 构建脚本 `build.py` 输出到 `dist/`，保留原有三类页面（首页/归档/文章页）。

## 三、已做决策

| 决策 | 理由 |
|---|---|
| 不引入框架，纯 CSS 变量换肤 | 站点体量小，框架收益为负 |
| 字体不外链，全用系统栈 | 隐私 + 加载速度 |
| 文章 markdown 源文件不动 | 内容与呈现解耦 |

## 四、待确认未决项

- ★ 是否保留旧版「友链」页面（用户未拍板，先不删）。

## 五、关键数字与口径

- 断点：768px（设计稿口径）
- Lighthouse 目标：Performance ≥ 90（暂无实测数据，写"暂无推算"）
